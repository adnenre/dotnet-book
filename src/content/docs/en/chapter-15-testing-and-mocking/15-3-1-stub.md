**Context**: A stub is a test double that provides predefined answers to calls made during the test. It does not verify interactions; it only supplies data. Stubs are used to isolate the system under test by replacing dependencies that would otherwise be hard to control (e.g., random number generators, current time, external APIs).

## Usage Example

```csharp
using Moq;
using Xunit;

public interface ITimeProvider
{
    DateTime Now { get; }
}

public class GreetingService
{
    private readonly ITimeProvider _time;
    public GreetingService(ITimeProvider time) => _time = time;
    public string GetGreeting()
    {
        return _time.Now.Hour < 12 ? "Good morning" : "Good afternoon";
    }
}

public class StubExample
{
    [Fact]
    public void GetGreeting_ReturnsMorningBeforeNoon()
    {
        var stub = new Mock<ITimeProvider>();
        stub.Setup(t => t.Now).Returns(new DateTime(2025, 1, 1, 9, 0, 0));
        var service = new GreetingService(stub.Object);
        Assert.Equal("Good morning", service.GetGreeting());
    }

    [Fact]
    public void GetGreeting_ReturnsAfternoonAfterNoon()
    {
        var stub = new Mock<ITimeProvider>();
        stub.Setup(t => t.Now).Returns(new DateTime(2025, 1, 1, 14, 0, 0));
        var service = new GreetingService(stub.Object);
        Assert.Equal("Good afternoon", service.GetGreeting());
    }
}
```

## Output console

```shell
dotnet test
Passed! - Failed: 0, Passed: 2, Skipped: 0
```

## Important notes

- Stubs are not verified for method calls; they only return values.
- Use stubs to simulate success, failure, or edge cases.
- In Moq, stubs are created with `Setup(...).Returns(...)` without calling `Verify`.

## Real-world usage example

**Testing a caching service** – Stub the underlying data source to return specific records and test that the cache returns the same data.  
See [xUnit Test Doubles](https://xunit.net/docs/getting-started/netcore/unit-testing).
