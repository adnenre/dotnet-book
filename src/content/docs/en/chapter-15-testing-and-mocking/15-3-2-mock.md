**Context**: A mock is a test double that verifies that specific interactions occurred (e.g., that a method was called with expected arguments). Mocks are used to test behavior – whether the system under test correctly invokes its dependencies. While stubs provide data, mocks check how the system interacts with its collaborators.

## Usage Example

```csharp
using Moq;
using Xunit;

public interface IAuditLogger
{
    void Log(string action, string user);
}

public class AccountService
{
    private readonly IAuditLogger _logger;
    public AccountService(IAuditLogger logger) => _logger = logger;
    public void DeleteAccount(string user)
    {
        // ... deletion logic
        _logger.Log("DeleteAccount", user);
    }
}

public class MockExample
{
    [Fact]
    public void DeleteAccount_CallsAuditLogger()
    {
        var mock = new Mock<IAuditLogger>();
        var service = new AccountService(mock.Object);
        service.DeleteAccount("alice");
        mock.Verify(x => x.Log("DeleteAccount", "alice"), Times.Once);
    }
}
```

## Output console

```shell
dotnet test
Passed! - Failed: 0, Passed: 1, Skipped: 0
```

## Important notes

- Mocks focus on interaction testing, not state verification.
- Overusing mocks can make tests brittle (refactoring breaks tests).
- Combine mocks with stubs when both data and interaction need testing.

## Real-world usage example

**Event publishing** – Mock the event bus and verify that a domain event is published after a command executes.  
See [Mock vs Stub comparison](https://stackoverflow.com/questions/3459287/whats-the-difference-between-a-mock-stub).
