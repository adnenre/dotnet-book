**Contexte** : Un mock est un double de test qui vérifie que des interactions spécifiques ont eu lieu (par exemple, qu'une méthode a été appelée avec les arguments attendus). Les mocks sont utilisés pour tester le comportement – comment le système testé interagit avec ses dépendances. Alors que les stubs fournissent des données, les mocks vérifient comment le système interagit avec ses collaborateurs.

## Exemple d'utilisation

```csharp
using Moq;
using Xunit;

public interface IJournalAudit
{
    void Log(string action, string utilisateur);
}

public class ServiceCompte
{
    private readonly IJournalAudit _journal;
    public ServiceCompte(IJournalAudit journal) => _journal = journal;
    public void SupprimerCompte(string utilisateur)
    {
        // ... logique de suppression
        _journal.Log("SupprimerCompte", utilisateur);
    }
}

public class ExempleMock
{
    [Fact]
    public void SupprimerCompte_AppelleJournalAudit()
    {
        var mock = new Mock<IJournalAudit>();
        var service = new ServiceCompte(mock.Object);
        service.SupprimerCompte("alice");
        mock.Verify(x => x.Log("SupprimerCompte", "alice"), Times.Once);
    }
}
```

## Remarques importantes

- Les mocks se concentrent sur les tests d'interaction, pas sur l'état.
- Une utilisation excessive des mocks peut rendre les tests fragiles (la refactorisation casse les tests).
- Combinez les mocks avec des stubs lorsque vous avez besoin à la fois de données et de vérification d'interaction.
