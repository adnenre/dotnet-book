**Contexte** : Un stub est un double de test qui fournit des réponses prédéfinies aux appels effectués pendant le test. Il ne vérifie pas les interactions ; il fournit seulement des données. Les stubs sont utilisés pour isoler le système testé en remplaçant les dépendances qui seraient autrement difficiles à contrôler (générateurs de nombres aléatoires, horloge, API externes).

## Exemple d'utilisation

```csharp
using Moq;
using Xunit;

public interface IHorloge
{
    DateTime Maintenant { get; }
}

public class ServiceSalutation
{
    private readonly IHorloge _horloge;
    public ServiceSalutation(IHorloge horloge) => _horloge = horloge;
    public string GetSalutation()
    {
        return _horloge.Maintenant.Hour < 12 ? "Bonjour" : "Bon après-midi";
    }
}

public class ExempleStub
{
    [Fact]
    public void GetSalutation_RetourneBonjourAvantMidi()
    {
        var stub = new Mock<IHorloge>();
        stub.Setup(t => t.Maintenant).Returns(new DateTime(2025, 1, 1, 9, 0, 0));
        var service = new ServiceSalutation(stub.Object);
        Assert.Equal("Bonjour", service.GetSalutation());
    }

    [Fact]
    public void GetSalutation_RetourneApresMidiApres12h()
    {
        var stub = new Mock<IHorloge>();
        stub.Setup(t => t.Maintenant).Returns(new DateTime(2025, 1, 1, 14, 0, 0));
        var service = new ServiceSalutation(stub.Object);
        Assert.Equal("Bon après-midi", service.GetSalutation());
    }
}
```

## Remarques importantes

- Les stubs ne sont pas vérifiés pour les appels ; ils ne font que retourner des valeurs.
- Utilisez les stubs pour simuler le succès, l'échec ou les cas limites.
- Dans Moq, les stubs sont créés avec `Setup(...).Returns(...)` sans appeler `Verify`.

## Exemple d'utilisation dans le monde réel

**Test d'un service de cache** – Stubbez la source de données sous-jacente pour retourner des enregistrements spécifiques et testez que le cache retourne les mêmes données.  
Voir [xUnit Test Doubles](https://xunit.net/docs/getting-started/netcore/unit-testing).
